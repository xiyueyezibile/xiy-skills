## 文档/可移植性（README/脚本/路径）


### P-004: README 插图应优先使用仓库内相对路径资产
- **标签**: 文档, README, 图片, 可移植性
- **首次出现**: 2026-07-03
- **最近出现**: 2026-07-03
- **出现次数**: 1
- **一句话结论**: README 中的配图应尽量落在仓库内并通过相对路径引用，避免使用外部临时链接或本地不可复用路径。
- **容易写错的原因**:
  - 外链图片容易失效、鉴权失败或加载变慢
  - 本地绝对路径和临时 URL 无法被其他协作者或 GitHub 稳定渲染
  - 仓库内相对路径最适合跟随文档版本一起演进
- **错误做法（反例）**:
  - 在 README 里引用本机路径或临时文件服务地址
  - 生成了图片但不落盘到仓库资产目录，导致文档依赖会过期的外部资源
- **正确做法（正例）**:
  - 把 README 配图保存到仓库内统一资产目录，例如 assets/...
  - 在 Markdown 中使用相对路径引用图片，让文档和资源一起版本化
- **最小示例**:
  - 正确示例：![illustration](assets/readme-illustrations/01-topic.svg)
- **适用范围/不适用范围**:
  - 适用: ['面向团队协作的 README、说明文档、项目首页', '需要在 GitHub 或代码托管平台直接查看的图片资源']
  - 不适用: ['仅供个人临时预览且不会提交到仓库的本地草稿']

### P-003: README 避免写入个人绝对路径作为安装命令
- **标签**: 文档, 工具, 可移植性
- **首次出现**: 2026-03-31
- **最近出现**: 2026-03-31
- **出现次数**: 1
- **一句话结论**: 文档里不要给读者复制个人机器的绝对路径命令，应该提供可移植的安装方式。
- **容易写错的原因**:
  - 本地调通后容易直接把本机路径粘到 README
  - 新同学照抄会直接失败，造成“工具不可用”的误解
- **错误做法（反例）**:
  - npx skills add <path-to-skill> -g -y
- **正确做法（正例）**:
  - 提供仓库形式的安装（owner/repo@skill）或相对路径/发布地址
  - 如果必须本地路径，明确“示例路径需替换”为占位符形式
- **最小示例**:
  - npx skills add <owner>/<repo>@<skill> -g -y
- **适用范围/不适用范围**:
  - 适用: 面向团队的 README/公共文档
  - 不适用: 个人笔记且不会被团队复用
