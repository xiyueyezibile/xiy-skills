## 工具/鉴权/内部平台读取（MCP/文档/平台）

### P-001: 内部文档/平台内容优先走MCP而不是直接网页抓取
- **标签**: 工具, 文档, MCP
- **首次出现**: 2026-03-20
- **最近出现**: 2026-03-20
- **出现次数**: 1
- **一句话结论**: 访问内部文档/平台内容（如飞书/内部平台）时，优先用对应的 MCP/CLI 能力，不要指望通用网页抓取稳定可用。
- **容易写错的原因**:
  - 直觉会用“抓网页”解决一切，但内部站点常有鉴权/跳转/反爬/内容渲染等限制
  - 抓取成功与否不稳定，导致误判“文档不存在/链接错误”
- **错误做法（反例）**:
  - 直接用通用网页抓取去拉取内部 docx/wiki 内容，遇到空内容/跳转就放弃
- **正确做法（正例）**:
  - 先识别链接属于哪类内部系统，然后用对应的 MCP/技能读取或搜索
  - 如果拿不到全文，退化为：用检索能力定位同主题文档/片段，再补齐上下文
- **最小示例**:
  - “优先走：文档/知识库检索 → 获取 doc 内容 → 迭代读引用”
- **适用范围/不适用范围**:
  - 适用: 内部文档、知识库、平台 API 文档、受限网页
  - 不适用: 公网静态文档/无需鉴权页面
