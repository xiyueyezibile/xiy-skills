# 消息面选币与交易计划

用可追溯的近期消息寻找候选币，再用 Binance 真实行情与用户授权的只读账户数据验证市场是否已经定价。每次建议前先读取本地 LLM Wiki；每次完整平仓后复盘并沉淀可复用经验。

## 权限边界

- 仅在用户明确授权时，通过安全输入脚本把 Binance API Key/Secret 保存到 `~/.crypto/config.json`，并只调用账户、持仓等 GET 只读接口。
- 密钥文件权限必须是 `0600`，目录权限必须是 `0700`；不得在命令参数、对话、日志、Wiki、交易记录或错误信息中输出密钥。
- 不调用下单、撤单、调杠杆、修改保证金模式等写接口，不生成可直接执行真实交易的命令；只给用户手动操作所需的市价/限价方向、价格、数量、保证金模式和杠杆建议。
- 不声称保证盈利。若证据不足、数据过期或风险收益比不合格，明确输出“观望”。
- 用户把凭证直接贴进对话时不要复述，提醒其轮换已暴露凭证，再通过交互式隐藏输入配置。建议只创建“启用读取、关闭现货交易与合约交易、关闭提现、限制可信 IP”的 API Key。

## 本地状态与学习闭环

固定使用 `~/.crypto`。首次使用先执行：

```bash
python3 scripts/crypto_memory.py init
```

目录结构、读写门禁、交易生命周期和知识沉淀格式见 [references/llm-wiki.md](references/llm-wiki.md)，涉及建议、开仓、平仓或学习资料时必须先完整读取该文件。

每次提出新建议前必须执行：

```bash
python3 scripts/crypto_memory.py context
```

读取返回的 `llms.txt`、`index.md`、`knowledge/advantages.md`、`knowledge/pitfalls.md`、`knowledge/rules.md` 以及相关交易复盘。读取失败时停止给出新建议并说明原因，不能绕过学习门禁。

用户明确说已采纳建议并开仓时，立即记录；缺少币种、方向、实际入场价、数量中任何一项时只追问缺项。记录前把原推荐理由写入临时 JSON，确保交易流水本身包含跨对话复盘所需的证据快照，不能只保存 `plan-id` 或依赖聊天历史：

```bash
python3 scripts/crypto_memory.py open --symbol BTCUSDT --side LONG --entry 64000 --quantity 0.01 --plan-id PLAN_ID --rationale-file /tmp/crypto-plan-rationale.json
```

理由 JSON 必须包含非空字段：`strategyMode`、`batchId`、`portfolioContext`、`summary`、`catalyst`、`technicalSetup`、`derivativesConfirmation`、`tradePlan`、`positionSizingReason`、`invalidation`、`confidence`、`dataCutoff` 和非空 `sources` 数组。单币计划也要写 `strategyMode=single`，并说明它不属于篮子批次。内容应记录当时可知的信息，包括消息催化与发布时间、4h/1h/15m 结构、成交量/OI/资金费率、方向与入场方式、止损止盈依据、净盈亏比、仓位风险档和杠杆依据、组合风险、失效条件、数据截止时间及来源链接。某项数据不可得时明确写“不可得”及其对置信度的影响，不能虚构。脚本会把完整对象嵌入 `OPEN.rationale`；临时文件不得包含密钥或账户标识。

用户明确说已全部平仓时，记录实际出场价、时间、费用和备注：

```bash
python3 scripts/crypto_memory.py close --trade-id TRADE_ID --exit 66000 --fees 0
```

随后必须基于原建议、开仓记录、持仓期间消息与量价、实际出场结果完成归因分析，并写入 `reviews/<trade-id>.md`。只把跨交易可复用且有证据的优势、坑位或条件式规则更新到 Wiki；不得因为单笔盈亏就武断改规则。

用户主动提供学习资料时，记录来源、时间、摘要、适用条件、反例和可信度到 `sources/`，再把验证后的稳定结论写入 `knowledge/` 并更新索引。密钥、个人隐私和大段受版权保护的原文不得进入 Wiki。

配置密钥时使用隐藏输入，避免 shell 历史泄露：

```bash
python3 scripts/crypto_memory.py configure-binance
```

每次给出可执行交易建议前必须执行：

```bash
python3 scripts/binance_private_snapshot.py
```

私有数据只用于判断账户权益、可用余额、现有仓位集中度和风险暴露，不在非必要时完整展示。若读取失败或没有配置，允许继续输出观察名单，但不得给出具体开仓数量、名义仓位或杠杆，也不得称为可执行建议；不得把“拥有密钥”解释为拥有交易授权。

## 默认范围

- 市场：Binance U 本位永续合约，允许做多和做空。
- 趋势周期：4h；确认周期：1h；入场周期：15m。
- 支持两种策略模式：单币精选模式沿用动态风险档；用户要求多币种、十几个仓或埋伏高盈利币时，默认使用 `basket` 篮子探索模式，不再把每条腿都按单币 A+ 门槛筛选。
- 单币精选模式：净盈亏比 `>1 且 <1.5` 时风险通常不超过权益 `0.5%`；净盈亏比 `1.5–3` 通常为 `0.75%`；证据全部共振且保守净盈亏比 `≥3` 的 A+ 机会才可使用 `1.25%`。
- 篮子探索模式：目标同时持有 `8–15` 个币，通常 `10–12` 个；2–4 个核心仓每个风险 `0.4%–0.6%`，其余侦察仓每个风险 `0.15%–0.3%`，任何一腿不得超过 `0.6%`。候选不足时允许少于 8 个，不为凑数量纳入低流动性或无法设置结构止损的币。
- 逐仓与全仓均可建议，默认优先逐仓；只有私有账户快照可用、全部合约持仓和组合风险可核算、无对冲关系不明的仓位、强平压力测试通过时，才可建议全仓。全仓只表示共享保证金，绝不表示把全部余额作为仓位或允许扩大止损风险。
- 建议有效杠杆通常为 `3x–7x`、硬上限 `10x`。高波动、低流动性、消息不确定或强平缓冲不足的标的必须降低杠杆或淘汰。
- 用户的进攻目标是月度账户收益 `100%+`，这是策略设计与复盘基准，不是承诺、预测或强制交易配额。不得为了追赶月目标放宽消息质量、结构止损、流动性或风险闸门。
- TP1 保证金收益率约 `50%` 是优先偏好，不是固定收益要求。先由行情结构、波动率和消息持续性确定止损、分批目标与尾仓退出，再计算实际保证金收益率；禁止为了凑 50% 虚构目标或迁就止损。
- 最低门槛使用扣除预估手续费、资金费率和滑点后的保守净盈亏比，必须严格 `>1`。优先选择 `≥1.5`，`≥3` 才有资格进入最高风险档；盈亏比不等于胜率，仍须通过消息、结构和拥挤度门禁。
- 排除：稳定币相关标的、杠杆代币、非 `TRADING` 永续合约、低流动性标的及已知临近下架标的。
- 单币精选模式默认最多展示 5 个候选、推荐 3 个计划；篮子探索模式展示最多 20 个候选，并可推荐 8–15 个分层计划。

用户明确指定现货、周期、币种、方向或风险偏好时，以用户要求为准，但权限边界不变。当前脚本只覆盖 U 本位永续；现货任务直接调用 Binance 现货公共接口或说明脚本范围，不要把合约数据冒充现货数据。

## 工作流

### 1. 明确时间锚点

记录当前绝对时间、时区和研究截止时间。新闻发布时间、行情抓取时间都使用绝对时间，避免使用“刚刚”“今天”却不注明日期。

### 2. 获取真实候选池

从 Skill 目录执行：

```bash
python3 scripts/binance_market_snapshot.py scan --limit 30
```

脚本只调用 Binance 公共只读接口，返回当前可交易永续合约、价格、24h 涨跌幅、成交额和成交笔数。优先从高成交额和显著异动中建立候选池；不要单纯追逐涨幅榜。

若用户指定币种，执行：

```bash
python3 scripts/binance_market_snapshot.py analyze --symbols BTCUSDT,ETHUSDT
```

这会抓取 4h、1h、15m K 线并计算 EMA20/EMA50、RSI14、ATR14、近期高低点与成交量相对值。脚本输出中的 `generated_at` 和各周期最后一根 K 线时间必须进入新鲜度判断。

### 3. 搜索消息催化剂

对候选池逐个联网搜索最近 72 小时消息，并按以下顺序取证：

1. 项目方、基金会、交易所和监管机构的官方公告；
2. 可直接定位原始材料的主流新闻报道；
3. 经交叉验证的行业媒体；
4. 社交平台仅作线索，不能单独成为入场依据。

每条采用的消息必须记录：事件、来源名称、原始链接、明确发布时间、检索时间，以及它为何可能影响供需、流动性、监管预期或市场叙事。单币核心仓至少两项独立证据支持核心催化；若只有一项官方一手来源，可以保留但降低置信度。篮子侦察仓允许使用一项可追溯来源，或在没有新消息时以技术/资金流模型入选，但必须明确标为“技术侦察”，不得把它描述成消息驱动机会。

区分事件发生时间和文章发布时间。重复转载算同一来源。无法打开原文、没有日期、只有截图或匿名爆料的消息，不得作为核心催化。

### 4. 评估消息是否已被定价

将消息时间与 15m/1h K 线对齐：

- 消息后放量突破且回踩守住关键位，才考虑顺势计划；
- 消息利好但价格冲高回落、量价背离，标记“可能已定价”，不追多；
- 消息利空但价格拒绝下跌，警惕空头拥挤，不追空；
- 消息发布前已大幅异动，检查是否存在提前交易，降低置信度；
- 找不到可验证催化时，单币精选模式只能列为技术观察；篮子模式可进入小风险“技术侦察仓”，前提是流动性、结构止损、衍生品数据和净盈亏比均合格。

### 5. 技术面确认

按从高到低周期判断：

- 4h：EMA20/EMA50 关系、市场结构高低点决定主要方向；
- 1h：确认突破、回踩、趋势延续或反转结构，并检查 RSI 是否过度拥挤；
- 15m：寻找实际触发位，不使用单根瞬时尖峰作为入场价；
- ATR14：校验止损是否覆盖正常波动；止损应位于结构失效位之外，而非只按固定百分比；
- 成交量：突破时应有量能确认，回踩时量能宜收缩。

技术条件用于选择“现在市价入场”或“近价限价入场”：

- 市价：所需收盘、突破或回踩已经发生，最新价格仍在允许滑点内；默认最大偏差 `0.15%`。
- 近价限价：4h/1h 方向和消息逻辑已经成立，仅等待价格回到已验证的 15m 支撑/阻力或突破回踩位。挂单价距离最新价不得超过 `min(0.5%, 0.25 × 15m ATR / 最新价)`，且挂单成交后的保守净盈亏比仍须严格大于 1。
- 限价单默认有效期 `30 分钟`。超过有效期、15m 收盘破坏原结构、核心消息被证伪、BTC 出现反向剧烈波动或最新价偏离重新报价阈值时，要求用户取消挂单并重新分析。
- 不推荐远价抄底摸顶、无限期 GTC 挂单或只因“价格更便宜”而缺少结构依据的挂单；不得把限价单描述成必然成交。

### 6. 计算交易计划

先读取本轮私有账户快照，再用最新市价、结构止损和账户风险反推仓位。不得先选杠杆再倒推可承受亏损。

做多：

- 风险 `R = 入场参考价 - 止损价`
- 目标收益风险比 `RR = (止盈价 - 入场参考价) / R`

做空：

- 风险 `R = 止损价 - 入场参考价`
- 目标收益风险比 `RR = (入场参考价 - 止盈价) / R`

止损和止盈金额不得固定。止损必须位于结构失效位之外并通过 ATR 校验；止盈使用前高/前低、密集成交区、影线回补、流动性区或趋势扩展。至少给出一个保守可达目标用于计算净盈亏比，并可给出 TP1、TP2 和移动止损尾仓。强趋势中允许让利润奔跑，但必须写清尾仓退出条件。若价格精度无法确认，保留合理小数位并提醒下单前以 Binance 规则复核。

每个可执行建议都分配唯一 `plan-id`，并在输出里保留足以生成开仓理由快照的原始依据。用户确认成交时，先把该建议结构化为理由 JSON，再调用 `open`；禁止根据成交后的走势补写或改写推荐当时的逻辑。

收益与风险换算：

- `TP1 价格变动比例 = abs(TP1 - 入场价) / 入场价`
- `TP1 保证金收益率（未扣费）≈ TP1 价格变动比例 × 杠杆`
- 若结构 TP1 支持约 50% 保证金 ROI，可用 `偏好杠杆 = 50% / TP1 价格变动比例` 作为参考；实际杠杆仍受 `10x` 上限、账户风险和强平缓冲约束
- `保守净盈利 = 目标毛盈利 - 双边手续费 - 预估资金费率 - 保守滑点`
- `保守净亏损 = 止损毛亏损 + 双边手续费 + 保守滑点`
- `保守净盈亏比 = 保守净盈利 / 保守净亏损`，必须严格大于 1
- 对移动止损尾仓不得用无限目标抬高盈亏比；风险档只按第一个保守可达目标计算，尾仓收益属于额外上行

月度目标只用于检验策略是否具备实现路径。使用最近至少 20 笔完整交易（不足 20 笔时明确“样本不足”）计算胜率、平均盈利 R、平均亏损 R、每笔期望值与最大回撤：

- `每笔期望 R = 胜率 × 平均盈利 R - 败率 × 平均亏损 R`
- 用实际交易频率和风险比例做复利情景推演，同时给出基准、乐观、压力三种结果
- 若乐观情景仍无法接近月目标，明确说明目标与当前策略统计不匹配；不得通过提高杠杆篡改胜率或期望值
- 不足 20 笔时沿用风险上限，不因样本不足提高风险；每满 20 笔重新校准一次

仓位计算：

- `账户风险额 = 账户权益 × 单笔风险比例`
- `止损距离比例 = abs(市价入场价 - 止损价) / 市价入场价`
- `风险约束名义仓位 = 账户风险额 / 止损距离比例`
- `建议杠杆 = 满足保证金占用且不超过风险上限的最小整数杠杆`
- `保证金占用 = 名义仓位 / 建议杠杆`
- `交易数量 = 名义仓位 / 市价入场价`

根据行情调整风险时，只能调整账户风险预算和数量，不能移动已经由结构确定的止损来美化盈亏比。止损距离较宽但保守目标更远、净盈亏比更高时，可以采用更高风险档；同时按止损距离缩小数量。止损距离较窄但目标空间不足时，即使杠杆收益率看起来很高也必须淘汰。

名义仓位还必须受可用余额、已有同方向/同板块仓位、维持保证金和极端滑点约束；取风险约束、组合约束和保证金约束中的最小值。计算时预留至少 `20%` 可用余额，不把全部余额用于保证金。若止损成交可能出现明显滑点，主动下调名义仓位。输出数量前按 Binance 当前数量精度和最小名义价值向下取整；无法确认交易规则时不给精确数量。

保证金模式校验：

- 逐仓：按该仓位的独立保证金和估算强平价校验。
- 全仓：按整个 U 本位合约钱包权益、所有全仓持仓未实现盈亏、维持保证金和相关性进行压力测试；至少假设其他同方向仓位同时触发止损并额外加入保守滑点。
- 只有估算强平价到入场价的距离至少为结构止损距离的 `2 倍`，且压力情景下仍未触发组合风险闸门，才可建议全仓；无法可靠估算时退回逐仓。
- 输出全仓建议时必须醒目标明：“全仓共享整个合约余额，其他仓位亏损会推近强平；建议数量不是满仓数量”。

组合风险闸门：

- 单币精选模式：所有未平仓计划按止损计算的总风险不得超过权益 `2.5%`；同方向或高度相关币种合计不得超过 `1.75%`。
- 篮子探索模式：整个批次连同已有仓位的计划止损风险不得超过权益 `4%`；同一项目生态或同一叙事桶不得超过 `1.2%`；同方向高 Beta 山寨币合计不得超过 `2.75%`。BTC/ETH 同向剧烈波动压力场景下，按所有相关腿同时止损并额外加入滑点计算。
- 篮子不是把风险上限乘以币种数量。十个高度相关的山寨多单仍视为一个方向性风险簇；通过缩小每腿数量实现多样本，而不是扩大总风险。
- 全仓篮子默认使用 `3x–5x`，总名义敞口通常不超过权益 `2.0x`，预计初始保证金占用不超过合约钱包权益 `45%`；更高杠杆只用于降低单腿保证金占用，不得扩大名义仓位或计划亏损。
- 当日已实现亏损达到当日初始权益 `3%`：当天停止推荐新仓；最近 7 日回撤达到 `6%`：未来 72 小时只复盘、不推荐新仓
- 当月从权益高点回撤达到 `12%`：停止进攻档，直到完成复盘且用户明确恢复；不得用摊平、补保证金或提高杠杆追回损失
- 连续 3 笔止损：暂停新仓至少 24 小时并复盘；连续盈利不得自动提高单笔风险

篮子批次管理：

- 同一轮推荐共用唯一 `batch-id`，逐币仍保留唯一 `plan-id`；开仓理由记录该币在批次中的层级、叙事桶、方向、风险贡献和与已有仓位的相关性判断。
- 默认分两批建立：先开约一半候选，至少等待一个 15m 收盘后再决定其余，避免同一瞬间把全部组合暴露给一次市场噪声；若用户明确要求一次性开齐，也必须按完整组合压力场景计算。
- 批次层面同时统计命中率、平均 R、中位数 R、最大单币盈利、最大单币亏损、前 20% 盈利贡献、相关止损数量和费用占毛利润比例。只有少数大赢家贡献收益时，不应仅以低胜率否定策略；但必须验证尾部盈利能覆盖多数小止损和交易成本。
- 同一批次多数仓位平仓后，除逐币复盘外再写一份批次复盘，比较“核心仓/侦察仓”“消息驱动/技术侦察”和不同叙事桶的效果。

杠杆建议必须同时解释：推荐倍数、预计保证金占用、止损触发时预计亏损额与占账户权益比例。明确说明杠杆不会改变按止损计划计算的亏损，但会影响强平距离和保证金占用。若预计强平价可能先于结构止损、账户已有高风险敞口，或最低可用杠杆仍不安全，则淘汰计划。

### 7. 设置否决条件

以下任一情况默认观望：

- Binance 行情抓取失败，或行情时间戳明显过期；
- 核心消息无法追溯，或只有未经证实的社交传闻；
- 公告存在下架、暂停充提、合约调整等未厘清风险；
- 24h 成交额过低、点差或插针风险显著；
- 多周期方向冲突且没有清晰触发位；
- 结构止损或目标缺乏依据、扣费后的保守净盈亏比不大于 1，或当前价已经远离计划入场区；
- BTC 出现与山寨币计划相反的剧烈系统性波动。
- 账户快照不可用、账户权益或可用余额不足，因而无法可靠计算仓位和杠杆；
- 当前价格已经越过允许滑点范围，市价成交后保守净盈亏比不再大于 1；
- 限价距离超过近价阈值、没有已验证结构位、默认有效期内成交概率和风险收益不匹配，或挂单后无法持续检查失效条件；
- 为达到约 50% 的 TP1 保证金收益率需要超过 10x 时，不强求该偏好；若降低杠杆后保守净盈亏比仍大于 1 可保留，否则淘汰；
- 命中单日、滚动 7 日、月度回撤或连续止损闸门；

- Binance 主域名不可达时，可尝试公开备用域名，但必须标明实际来源；所有端点都失败就停止给价。

- 不把缓存、历史报告或参考仓库中的旧数值当作当前行情。
