# Crypto LLM Wiki 与交易日志规则

固定根目录为 `~/.crypto`：

```text
~/.crypto/
  config.json
  llm-wiki/
    llms.txt
    index.md
    knowledge/advantages.md
    knowledge/pitfalls.md
    knowledge/rules.md
    sources/
    reviews/
  trades/ledger.jsonl
```

## 读取门禁

每次新建议前先运行 `crypto_memory.py context`，再按返回路径读取基础知识页和与候选币、消息类型、市场状态相符的来源与复盘。没有成功读取，不输出具体入场、止盈或止损。

## 交易生命周期

- 每次 Skill 触发都先执行账户—流水审计，不等待用户说“已开仓”“有平仓”或提醒读取记录。审计比较 Binance 当前持仓与本地未平仓事件，并仅为出现差异的币种读取近期成交。
- 当前持仓存在、本地无记录时视为漏记候选；本地记录存在、当前持仓消失时视为疑似平仓；数量不一致时视为加仓或部分平仓候选。先用真实成交重建，不能仅凭当前持仓均价猜测历史成交。
- 能从只读成交和已保存推荐理由唯一重建时主动补记；理由、批次或成交用途存在歧义时只询问无法从账户发现的最少信息，不得静默伪造或关闭交易。
- `open` 只在用户明确表示已经开仓，或只读账户成交已经形成唯一、可验证的实际持仓后记录；不把“准备开仓”误记为成交。
- 加仓或部分平仓使用 `adjust` 追加数量变化并保持交易打开；全部退出才使用 `close`。
- `ledger.jsonl` 为追加事件流，不原地篡改历史；同一 `trade_id` 的 `OPEN` 与 `CLOSE` 组成完整交易。
- 记录建议计划 ID、币种、方向、实际价格、数量、费用、UTC 时间和用户备注。每个 `OPEN` 还必须内嵌不可依赖聊天历史的 `rationale` 快照，至少包含推荐摘要、消息催化、技术结构、衍生品确认、仓位与杠杆依据、止损止盈及净盈亏比依据、组合风险、失效条件、置信度、数据截止时间和来源。不要记录密钥或账户标识。
- 理由只能使用推荐当时可知的信息；缺失数据明确标注，不得在成交后用未来走势美化原始逻辑。平仓复盘优先读取 `OPEN.rationale`，再与实际执行和后续行情对照。
- 多币种篮子中的每笔 `OPEN` 必须共享 `batchId`，并记录 `strategyMode=basket`、核心/侦察层级、叙事桶、该腿风险贡献和批次组合上下文；单币计划使用 `strategyMode=single`。中长线计划使用 `strategyMode=medium_long`，并保存预计持有期、1d/4h 逻辑、持续催化窗口、预计累计资金费率、日线失效条件和下一次复核时间；中长线与短篮子的统计、胜率和期望值分开汇总。

## 平仓复盘

复盘必须区分：

1. 结果：毛盈亏、费用、净盈亏、收益率；
2. 过程：消息是否真实、是否已定价、技术触发是否满足、入场是否偏离计划、止损止盈执行情况；
3. 外部因素：BTC 系统性波动、监管/宏观突发、流动性和滑点；
4. 归因：策略优势、执行优势、策略错误、执行错误、随机性，允许多因并存；
5. 反事实：遵守原计划会怎样，换一个无法在当时获知的信息不算有效反事实；
6. 可迁移结论：写清适用条件、失效条件、证据交易 ID 和置信度。

盈利不自动证明逻辑正确，亏损也不自动证明逻辑错误。至少两笔独立交易支持，或一笔交易加可靠外部证据，才把结论提升为高置信规则。

## 篮子批次复盘

同一 `batchId` 的多数仓位关闭后，额外生成 `reviews/batch-<batch-id>.md`。除逐币归因外，统计核心仓与侦察仓、消息驱动与技术侦察、叙事桶、多空方向的分组结果，以及命中率、平均/中位 R、最大盈亏、前 20% 盈利贡献、相关止损数和费用占比。篮子策略以“少数尾部赢家能否覆盖多数小止损与成本”为核心假设，不能只看胜率或单个冠军币。

## 学习资料

用户提供资料时保存摘要和来源定位，不默认复制全文。标注 `用户提供 / 官方 / 研究 / 媒体 / 未验证`，并记录适用市场、周期和发布日期。新资料与既有知识冲突时并列记录证据，等待更多验证，不静默覆盖。

## 索引维护

- `llms.txt` 只保留读取顺序和精选入口。
- `index.md` 列出近期复盘、来源与知识页更新时间。
- `advantages.md` 保存已验证优势；`pitfalls.md` 保存可复现失败机制；`rules.md` 保存条件式决策规则。
- 每次写入后同步更新 `index.md`；不要把单笔流水塞入全局知识页。
