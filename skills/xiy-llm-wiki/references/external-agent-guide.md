# 外部机器人 LLM Wiki 读取协议

这是一份给外部机器人使用的只读协议。机器人拿到个人 LLM Wiki Git 仓库后，应依据本文档读取知识并回答问题；除非用户明确授权，不得修改 Wiki、提交或推送。

## 1. Wiki 定义

这个仓库本身就是完整的个人 LLM Wiki，不是普通文档目录，也不是聊天记录备份。

LLM Wiki 是由 LLM 持续编译和维护的知识库：

- `raw/`：原始资料，只作为证据来源，不直接当作最终结论。
- `wiki/`：经过整理的结构化知识、决策、规则、踩坑和资料摘要。
- `wiki/index.md`：知识目录和页面入口。
- `wiki/current-work.md`：用户当前正在处理的工作上下文。
- `WIKI_SCHEMA.md`：本 Wiki 的结构、写作和维护规则。
- `log.md`：知识写入、查询和维护操作日志。

优先使用 `wiki/` 中已经编译的知识回答；只有在需要核对原始证据、时间、原文细节或 Wiki 页面明确引用了来源时，才读取 `raw/`。

## 2. 每次回答前的读取顺序

每次回答用户问题前，按以下顺序读取：

1. `WIKI_SCHEMA.md`
2. `wiki/current-work.md`
3. `wiki/index.md`
4. 根据问题关键词读取相关 Wiki 页面
5. 只有相关页面证据不足时，读取对应 `raw/` 原始资料
6. 必要时读取 `log.md`，判断知识的新旧和最近是否发生过更新

如果 Wiki 是 Git 仓库且机器人具备拉取权限，读取前应先使用配置中的 remote 执行：

```bash
git pull --ff-only <configured-remote> <current-branch>
```

“只读机器人”表示不修改 Wiki 内容，不代表整个 Wiki 仓库可以放在文件只读 sandbox 中。`git pull --ff-only` 仍需写入 `.git/FETCH_HEAD`、远端引用等 Git 元数据。部署时应只放行 Wiki 仓库的 Git 元数据更新，或在机器人运行前由可信外部任务完成同步；否则机器人只能使用可能过期的本地副本。

本地有未提交改动、拉取冲突或无法快进时，不应擅自覆盖本地文件；应明确说明 Wiki 未能同步。

## 3. 当前工作识别

`wiki/current-work.md` 是当前工作事实的首要来源。回答任何问题时，先提取：

- 当前业务仓库；
- 当前分支；
- 当前 HEAD；
- 未提交文件；
- 最近提交；
- 工作摘要。

回答开头必须先给出一行：

```text
当前工作：<根据 current-work.md 得出的事实摘要>
```

如果 `current-work.md` 不存在、为空或内容过期，不要猜测。应写：

```text
当前工作：Wiki 中没有足够的新鲜信息确认当前工作。
```

然后再回答用户的问题。

## 4. 知识回答规则

### 4.1 证据优先级

遇到冲突时，按以下优先级判断：

1. 用户本轮明确说明；
2. `WIKI_SCHEMA.md` 中的维护规则；
3. Wiki 页面中带来源和更新时间的最新结论；
4. 相关原始资料；
5. 历史日志和旧页面；
6. 机器人自己的常识或推测。

如果不同页面存在冲突，不能静默选择其中一个。应同时说明：

- 冲突的两个结论；
- 各自来源和时间；
- 当前采用哪个结论；
- 仍然存在的不确定性。

### 4.2 引用来源

每个重要结论都应引用 Wiki 相对路径，例如：

```text
依据：`wiki/decision/2026-08-24.md`
```

涉及原始资料时，同时引用：

```text
来源：`raw/<file>`
```

不能把没有来源的推测写成用户事实。

### 4.3 区分事实和推断

使用以下标签区分内容：

- `事实`：Wiki 或原始资料直接支持。
- `结论`：Wiki 已整理出的可复用判断。
- `推断`：机器人根据资料推导，尚未被 Wiki 明确确认。
- `待确认`：证据不足、冲突未解决或可能已过期。

### 4.4 时间有效性

优先使用带日期的页面和最近日志。对于可能变化的内容，必须说明知识时间：

```text
知识时间：<页面更新时间或日志时间>
```

不能把历史的当前工作、旧决策或旧状态直接描述成现在仍然有效。

## 5. 推荐回答格式

```markdown
当前工作：<current-work.md 中的事实摘要>

结论：<直接回答用户问题>

依据：
- `wiki/<相关页面>`：<支持点>
- `raw/<相关资料>`：<必要的原始证据>

不确定性：
- <冲突、缺失、过期或需要用户确认的内容>

相关知识：
- <可继续阅读的 Wiki 页面>
```

简单问题可以省略空的“不确定性”和“相关知识”区块，但不能省略当前工作和关键依据。

## 6. 只读边界

外部机器人默认只能：

- 拉取 Wiki；
- 读取 Markdown、JSON 和原始资料；
- 根据 Wiki 回答问题；
- 报告当前工作和知识来源。

外部机器人默认不能：

- 修改 `wiki/` 或 `raw/`；
- 更新 `wiki/current-work.md`；
- 执行 `git add`、`git commit` 或 `git push`；
- 把用户问题自动写入 Wiki；
- 把自己的推测当作新的 Wiki 事实。

只有用户明确说“记录到 Wiki”“沉淀这个结论”或授予写入权限时，才进入写入流程；写入应交给本地 `xiy-llm-wiki` Skill 执行。

## 7. Wiki 不可用时

按以下顺序报告问题，不要编造回答：

1. 找不到 Wiki 仓库：说明缺少 Wiki 路径。
2. 无法拉取远端：说明远端同步失败并停止使用本地版本回答；只有用户明确允许使用本地版本时，才可以继续，并标记版本可能过期。
3. 找不到 `wiki/current-work.md`：说明无法确认当前工作。
4. 找不到相关页面：说明 Wiki 当前没有覆盖该问题，可基于用户本轮提供的信息回答，并明确这是临时分析，不是 Wiki 已确认结论。
