# Crypto News Intel

负责把“这个币有什么消息”变成可审计的消息面证据。该 Skill 不负责交易数量、杠杆、账户风险或真实下单；这些必须交给 `crypto-risk-ledger` 与 `crypto-trade-executor`。

## 研究边界

- 只使用公开可追溯信息：项目方/基金会公告、交易所公告、监管机构原文、官方博客、主流新闻、可交叉验证的行业媒体。
- 全市场选币时，输入不是人工挑选后的少量候选，而是机械过滤后的全部幸存标的。必须逐项执行本轮真实消息发现；不得依赖已有排期、历史上下文、旧报告、熟悉度或少量抽样搜索先缩小名单。
- 社交平台、KOL、截图、匿名爆料只能作为线索；没有一手来源或交叉验证时不得作为核心催化。
- **时间和时效性是硬门槛**：每条进入结论或候选表的消息都必须明确写出 `发布时间`、`事件发生/生效时间`、`检索时间`、`距当前多久`、`时效性等级` 和 `交易有效窗口`。如果来源没有明确发布时间，标为 `时间缺失`，只能做线索，不能作为核心催化。
- 市场热点是横向资金与叙事参考，不是一手事件证据。不得仅凭热搜、社交声量、单币涨幅或媒体统一贴标签，就把标的升级为消息面候选。
- 明确区分：
  - 事件发生时间：事件实际发生、上线、执行、解锁、治理生效或 delist/结算时间。
  - 文章发布时间：媒体或公告发布的时间。
  - 检索时间：本轮读取该来源的绝对时间。
  - 行情对齐时间：需要交给行情结构 Skill 对齐 15m/1h K 线的时间戳。
  - 时效性：相对当前研究时间，判断是否仍在可交易窗口。
- 不承诺消息一定带来涨跌；只输出影响路径、持续性、确定性和已定价风险。

## 全量幸存池逐项核验

上游完成合约状态、合约类型、稳定币、重复季度合约、流动性和确认下架等机械过滤后，本 Skill 必须核验剩余的每个标的。允许并行和批量检索，但必须逐标的生成独立记录，不允许把一个赛道、指数或母公司消息自动复制给同组全部标的。

每个标的至少执行：

1. 访问一个与 `market_type` 对应的一手渠道：项目/基金会/治理、公司 IR、SEC、DART、HKEX、巨潮资讯、交易所公告或商品官方数据源。
2. 访问一个公开发现渠道，用于发现一手渠道名称未知、别名、未来日历或主流媒体线索。
3. 使用资产符号、项目/公司全名、别名与事件词组合检索最近 72 小时、最近 30 天持续事件和未来 30 天排期。
4. 记录本轮实际访问 URL、查询词、检索时间和结果。没有有效消息时写 `no_valid_catalyst_found`，不能只写“无消息”。
5. 若渠道失败，记录 `fetch_failed_unresolved` 并尝试替代渠道；仍未解决时，该标的不能计入已核验，全市场任务必须标记未完成。

逐项审计记录字段：

```json
{

  "contract_type": "PERPETUAL",
  "quote_volume_24h_usdt": 12345678,

  "queries": ["EXAMPLE official upgrade September 2026"],
  "retrieved_at": "2026-08-23T16:00:00+08:00",
  "latest_event": "未发现未来 30 天可验证催化",
  "published_at": null,
  "event_time": null,
  "timeliness": "无有效消息",
  "outcome": "no_valid_catalyst",
  "status": "淘汰",
  "reason": "已检查官方与公开发现渠道，未找到新鲜、持续或未来排期催化",
  "analysis_completed": true,

  "analysis_summary": "消息面无有效催化，行情结构仅用于确认不追入",
  "news_conclusion": "最近 72 小时及未来 30 天未发现可验证催化",
  "market_structure_summary": "已完成 1d/4h/1h/15m 分析，缺少消息驱动交易路径",
  "analyzed_timeframes": ["1d", "4h", "1h", "15m"],
  "market_data_time": "2026-08-23T15:59:59+08:00",
  "deep_analysis_required": false
}
```

完成条件：

- 全市场流动性门槛固定为 24h 成交额 `>= 10,000,000 USDT`；`research_audit` 中唯一标的数必须等于通过该门槛的机械过滤幸存数。
- payload 必须保存完整 `liquidity_survivors` 明细；其 symbol 集合必须与 `research_audit` 完全一致。每条 `checked_sources`、`retrieved_at`、`outcome`、`status`、`reason`、`analysis_summary`、`news_conclusion`、`market_structure_summary`、`market_data_time` 均非空，`analysis_completed` 必须为 `true`，`analyzed_timeframes` 必须完整包含 `1d/4h/1h/15m`。
- 每个幸存标的都必须传给行情结构 Skill 完成 1d/4h/1h/15m 分析，再把 `chase_risk` 标准化为 `低/中低/中/中高/高/极高`；不能因为没有有效催化而跳过结构分析。
- `低/中低/中/中高` 的全部标的必须进入最终候选矩阵和逐币深度报告；`高/极高` 可以只保留逐项研究审计，但不得省略分析结论。
- 历史上下文只能用于补充别名和查询词；没有本轮访问证据时，不得沿用历史结论。

## 市场热点分析

每轮全市场选币在逐项消息发现之外，还要生成一份独立热点快照，用于回答“资金当前集中在哪里、主题处于哪个阶段、是否已经拥挤”。热点分析必须覆盖：

1. 基准环境：BTC、ETH 和高 Beta 山寨的方向与强弱是否一致。
2. 市场广度：上涨/下跌标的数量、比例及变化，避免少数龙头掩盖多数标的走弱。
3. 流动性集中：全市场成交额在头部资产、单一主题和长尾资产之间的分布。
4. 主题扩散：同一主题至少有多个代表标的出现一致的成交额、相对强弱或价格结构，或者存在明确共同催化并获得多标的确认。
5. 拥挤风险：24h/多周期涨幅、RSI、资金费率、OI、基差或爆仓数据是否显示过热；不可得字段要明确标记。

主题阶段只使用：

- `萌芽`：共同催化已出现，但参与标的和成交额扩散有限。
- `扩散`：多个相关标的同步走强/走弱，成交额和广度扩大。
- `拥挤`：价格、RSI、资金费率或 OI 显示追入风险显著上升。
- `退潮`：龙头冲高回落、广度收缩或资金从主题流出。

热点输出必须附绝对数据时间、代表标的、量价/广度证据、共同催化、公开来源 URL、反向解释以及对选币的用途。用途只能是：

- 补漏：发现尚未进入信息差池但值得回到官方来源核验的标的。
- 共振：验证候选是否获得同主题资金扩散支持。
- 降权：热点已经拥挤时提高追入风险。
- 风险聚类：防止多个候选或持仓实质押注同一叙事。

热点不能单独作为 `opportunity`、`可开仓` 或降低风险等级的依据。热点代表标的仍须完成各自的官方/公开消息核验和 1d/4h/1h/15m 结构分析。

## 时间与时效性规则

每次回复开头必须写：

- `当前研究时间`：使用绝对时间和时区，例如 `2026-08-21 16:20 CST / 08:20 UTC`。
- `消息检索截止`：本轮最后一次成功读取新闻/公告的时间。
- `时效性口径`：短线默认最近 72 小时；中长线检查最近 30 天持续催化和未来 30 天已排期事件。

每条消息必须给一个时效性等级：

| 等级 | 口径 | 处理 |
|---|---|---|
| `实时` | 发布时间或事件生效时间距当前 ≤ 6 小时 | 可进入短线核心候选，但仍需行情确认 |
| `新鲜` | 6–24 小时 | 可进入候选，重点检查是否已被定价 |
| `仍有效` | 24–72 小时，且事件影响未完成或仍有后续窗口 | 可观察或等待结构触发 |
| `中长线有效` | 3–30 天，且有持续采用、治理、监管、解锁、升级等后续路径 | 只进中长线/主题观察，不能冒充短线新消息 |
| `过期/已兑现` | 超出上述窗口，或效应已充分兑现且缺少后续路径 | 淘汰或只作为背景 |
| `时间缺失` | 无法确认发布时间或事件时间 | 只能作为待验证线索 |

如果同一事件有多个时间，按下面方式写清：

- `公告发布时间`：来源发布的时间。
- `事件生效时间`：上线、下架、治理执行、合约结算、资金费率调整等真正影响市场的时间。
- `剩余窗口`：当前距离生效时间还有多久；已经生效则写 `已生效 X 小时/天`。
- `时效性结论`：例如 `新鲜，但价格已先涨 20%，需防已定价`。

没有完成以上时间字段，不要输出“可做”“强催化”“立即关注”等强结论。

## 取证优先级

1. 官方公告、治理提案、链上/项目方仪表盘、交易所公告、监管文件。
2. 可定位原始材料的主流新闻。
3. 有独立来源互证的行业媒体。
4. 社交平台线索，仅用于提示“待确认”。

## 传闻监控与状态升级

当用户要求“监控传闻”“根据传闻选币”“提前发现消息”“盯社媒/政策人物/名人项目”或普通消息面选币时，必须同时运行传闻监控，不得等标的进入涨幅榜后才反向找理由。

监控只覆盖公开可访问内容，不登录私人群组、不绕过权限、不抓取私密账号。来源分层如下：

| 层级 | 来源 | 用途 |
|---|---|---|
| `L0` | 监管机构、交易所、项目方、基金会、公司 IR/公告 | 可以确认或否认传闻，满足其他门禁后才有资格进入核心候选 |
| `L1` | 可定位原始材料的主流媒体、事件直接参与方的认证账号 | 用于高优先级核验；单一来源仍不能把传闻写成事实 |
| `L2` | 行业媒体、研究机构、长期可追溯的认证 KOL | 用于交叉验证和发现线索 |
| `L3` | 未认证社媒、匿名爆料、截图、群聊转述 | 只能进入低置信度观察池，不得进入核心候选或生成交易计划 |

每次触发按以下顺序执行：

1. 读取 `.crypto/rumor-watch/watchlist.json`，先处理到期、已否认和待复核条目；不存在时初始化。
2. 对上次 `last_checked_at` 之后的新内容做增量检索。至少覆盖：
   - SEC/监管文件、交易所公告、项目官方博客、治理论坛和认证官方账号。
   - 项目简称、代币符号、公司/人物别名与 `ETF`、`listing`、`partnership`、`acquisition`、`hack`、`exploit`、`unlock`、`airdrop`、`chain`、`launch`、`approval`、`ban` 等事件词组合。
   - 政策人物、名人品牌、生态关联方和直接参与方的公开表态；不得只检索项目官方名称。
3. 每条传闻记录：首次发现、最后核验、原始主张、方向提示、事件时间、来源层级、原始 URL、发布时间、支持/否认立场、价格触发、失效条件、复核时间和过期时间。
4. 去重并按状态升级：
   - `lead`：只有单一媒体、认证社媒或未认证线索。
   - `corroborated`：至少两个相互独立的可靠来源支持，但尚无官方确认。
   - `confirmed`：监管、交易所、项目方、公司等直接来源明确确认。
   - `disputed`：直接来源之间出现确认与否认冲突，降回低置信度观察。
   - `rejected`：直接来源明确否认，或关键事实被证伪。
   - `expired`：超过有效窗口且没有新增证据。
5. `lead`、`corroborated` 和 `disputed` 只能进入 `传闻观察池`；即使价格开始异动，也不得标为 `可开仓`。只有 `confirmed` 才具备进入核心候选的消息资格，之后仍需通过行情结构、已定价风险和盈亏比门禁。
6. 对已经启动但仍可能延续的强催化，转入 `已启动确认池`，明确回踩承接、二次突破、OI/资金费率冷却和下一次来源核验条件，不能简单淘汰后停止跟踪。

使用随包脚本维护跨轮状态：

```bash
python3 scripts/rumor_watch.py init
python3 scripts/rumor_watch.py expire
python3 scripts/rumor_watch.py list --status lead --status corroborated
python3 scripts/rumor_watch.py upsert --input /tmp/rumor-item.json
```

`upsert` 输入示例：


该 Skill 不是常驻守护进程：只有被用户、Agent 调度器、cron 或其他自动化入口调用时才会执行增量扫描。没有实际调度证据时，必须写“已建立待监控清单”，不能声称“正在 24 小时实时监控”。

## 二级内容学习来源

B 站、YouTube、播客、KOL 长文等二级内容可以用于学习选币方法论或发现线索，但不能单独作为交易核心事实来源。

- 可沉淀的方法论：信息源组合、叙事/赛道筛选、链上数据工具、成交量和价格行为确认、空投/活动安全识别。
- 不可直接采用：视频标题、UP 主观点、评论区、群聊截图、未给出处的数据、夸张收益叙事。
- 若视频无可抓取字幕或无法核验细节，只记录标题、作者、发布时间、简介要点和 URL；不得编造逐字稿或把未验证观点写成规则。
- 从二级内容得到的候选，必须再回到一手来源：官方公告、交易所公告、链上数据、公司 IR/财报或监管文件。

## 催化剂判断

默认对机械过滤后的完整幸存池逐项建立信息差审计，再把所有发现的有效机会交给行情结构验证。`涨幅榜`、`跌幅榜`、`成交额榜`、FinViz 技术/主题筛选和 K 线形态都只能作为验证雷达或补漏线索，不能作为消息面候选的主入口；榜单前列通常表示利好/利空已经至少部分被资金交易。若某标的是从榜单发现的，必须反向核验是否存在可追溯消息、未来节点或尚未完全定价路径；核验失败只能标 `只观察` 或 `技术侦察`。

每轮候选必须拆分为：

- `提前埋伏池`：未来 1–30 天有明确节点、尚未完全兑现、价格未明显抢跑、结构止损近，优先用于信息差选币。
- `已启动确认池`：消息强但涨跌幅/成交额已经启动，或效应已初步/基本落地但仍有未完成传导；必须继续评估二阶段空间，只能等待回踩承接、突破后回踩或趋势延续确认。
- `传闻观察池`：尚未获得直接来源确认的 `lead` / `corroborated` / `disputed`，用于持续核验和提前准备触发条件，不得包装成核心催化。

不得先看到暴涨/暴跌，再给它匹配泛泛叙事、旧闻、时间缺失消息或同赛道热度；这类倒推理由不能进入核心催化。

按以下维度给结论：

- **新鲜度**：短周期默认最近 72 小时；中长线检查最近 30 天持续催化和未来 30 天已排期事件。
- **确定性**：官方已发生 > 已排期 > 高可信媒体 > 社媒传闻。
- **持续性**：协议升级、真实采用、代币经济变化、监管节点、资金流入通常比一次性热搜更可持续。
- **供需路径**：说明它影响需求、供给、流动性、监管预期、叙事关注还是资金费率/杠杆拥挤。
- **独立证据数**：核心计划最好至少两项独立证据；单一官方一手来源可保留但降置信度。
- **反向证据**：下架、解锁、监管处罚、团队争议、买预期卖事实、同类竞品消息等。

`初步落地` 或 `基本落地` 不能作为停止研究或直接淘汰的理由。对这两类事件必须拆出：

- `已完成传导`：已经反映在供需、基本面、价格、成交量、OI 或资金费率中的部分。
- `未完成传导`：尚未执行的供应变化、收入/采用验证、监管生效、产品数据、链上流入流出或价格目标路径。
- `下一验证节点`：绝对时间或可观察条件。
- `二阶段方向与触发`：延续、回踩后二次启动或兑现反转，以及对应确认条件。
- `剩余空间证据`：交给行情结构 Skill 计算的保守目标、失效位和扣费后净盈亏比。
- `耗尽信号`：效应充分定价、量价背离、OI/资金费率拥挤、关键结构失效或后续节点取消。

只要仍有可验证的未完成传导，就必须保留在 `已启动确认池` 并完成后续结构分析。只有效应已充分兑现且没有下一阶段，或剩余空间不足以形成净盈亏比 `> 1`，才可淘汰；理由不得简写为“已经落地”。

## 未落地前埋伏模式

当用户说“埋伏”“提前埋伏”“未落地之前”“未来事件”“提前布局”“不要找已经落地的”时，切换到 `pre_landing` 模式。

`pre_landing` 模式的目标不是找已经上涨的新闻，而是找**已经公开排期、尚未完全兑现、仍有明确复核节点**的催化剂。筛选时优先：

- 未来 1–30 天的交易所上线/下架/结算、网络升级/硬分叉、治理执行、代币解锁、主网/产品发布、财报、监管听证/投票/裁决、指数/ETF/质押/空投等排期事件。
- 已披露但未落地的订单、合作、财报指引、监管审批、产品发布、Tokenomics 调整。
- 已落地但仍有二阶段窗口的事件，例如公告已出但生效时间未到、投票已通过但执行未开始、财报日期已公布但业绩未披露。

硬性排除：

- 事件已经完成且没有下一阶段验证点，只能作背景，不能进入埋伏核心。
- 只有媒体复述“已经上涨/已经获批/已经发布”，但没有未来生效时间或后续验证点。
- 只有分析师观点、KOL 观点、主题扩散或“可能订单”，没有可核验未来节点时，不得标为核心埋伏；只能放入待验证线索。
- 对股票代币，Binance 合约上线、tick size、资金费率调整属于交易工具变化；若已经生效且无底层公司未来节点，不能当作未落地基本面催化。

这里的“不能进入埋伏核心”不等于停止分析。若事件效应仅初步/基本落地且仍有二阶段路径，应转入 `已启动确认池`，继续评估剩余利润空间和风险；不得归入无分析的背景项。

每个 `pre_landing` 候选必须额外输出：

- `未来催化节点`：绝对时间、时区、事件类型。
- `当前阶段`：公告已出未生效 / 投票中 / 财报前 / 审批中 / 解锁前 / 产品发布前 / 待订单确认。
- `剩余时间`：距当前多久。
- `预期是否已被抢跑`：结合消息发布时间、24h 涨跌幅和关键 K 线。
- `提前埋伏条件`：只允许写低吸区、确认触发和失效条件；不要因为事件未落地就默认可买。
- `兑现风险`：事件当天或前后可能买预期卖事实。

风险标签在 `pre_landing` 模式下更严格：

- `低/中低/中` 只能给“未明显抢跑 + 未来节点明确 + 价格仍在低位/回踩承接 + 结构止损近 + 反向风险可控”的候选。
- 已明显抢跑、距离事件太近、财报前预期、正股时段未验证、或只差突破确认的候选，必须标 `中高/高`。
- `低/中低/中` 必须同时说明“为什么现在是埋伏而不是追涨”；写不出来就上调风险。

## 股票代币 / TradFi perpetual 消息面

当候选标的是 Binance 股票代币、bStocks、tokenized equity 或 `TRADIFI_PERPETUAL`（例如 `UNITREEUSDT`、`KUAISHOUUSDT`、`CXMTUSDT`）时，不能沿用普通加密项目消息面模板。

必须同时分清两层消息：

1. **底层股票公司消息**
   - 公司公告、交易所公告、财报、业绩预告、回购/增发、重大合同、产品发布、行业政策、监管/诉讼、供应链事件。
   - 优先使用公司 IR、证券交易所公告、监管披露、主流财经媒体。
   - 判断“为什么利多/利空”时要解释对公司收入、利润率、估值、订单、政策预期或风险折价的影响。
2. **Binance 交易工具消息**
   - 合约上线、最大杠杆、资金费率上限、资金费率结算频率、tick size、保证金参数、交易时间。
   - 这类消息只说明交易工具和交易摩擦变化，不等同于底层公司基本面利多。

股票代币报告每个标的额外写：

- `底层资产`：公司名称、股票代码和市场（如 Shanghai Stock Exchange / HKEX / US）。
- `Binance 合约类型`：必须标注 `TRADIFI_PERPETUAL`、`underlyingType` 和上线/规则生效时间。
- `消息传导路径`：底层股票消息如何传导到 Binance USDT 合约；若只有 Binance 上线/参数消息，说明这是流动性/可交易性变化，不是公司基本面催化。
- `交易时段错位`：底层股票有交易时段，Binance 合约 24/7，需提示隔夜跳空、休市期间消息、指数/汇率/流动性偏差。
- `落地状态`：公司事件已披露/已发生/待财报验证/待监管批准；Binance 合约是否已上线或参数是否已生效。

股票代币若缺少底层股票公司消息，只能标为 `交易工具变化` 或 `流动性观察`，不能写成“公司利好”。

FinViz / `finviz-screener` 可以辅助定位美股主题候选和基本面/技术过滤，但只作为候选池工具；本 Skill 的主判断仍然以消息面为先。不得把 FinViz 筛选结果、涨幅榜或估值因子本身写成消息催化。

## 判断是否已被市场定价

你不直接完成技术面计算，但要为 `crypto-market-structure` 明确需要对齐的时间点：

- 消息前是否已有异常拉升/下跌。
- 消息后是否立刻冲高回落。
- 消息是否已被多家媒体反复转载导致预期拥挤。
- 是否临近“兑现”节点，例如上线、空投、解锁、主网升级当天。
- 是否需要特别检查 15m/1h 放量、资金费率、OI 或多空拥挤。

## 淘汰规则

出现以下情况时，直接标为 `淘汰` 或 `只观察`：

- 无法找到可打开链接或明确发布时间。
- 输出时无法给出发布时间、事件时间、检索时间或时效性等级。
- 只有截图、群聊、匿名爆料，且无独立来源。
- 事件效应已充分兑现且缺少后续路径；仅初步/基本落地不得据此淘汰。
- 消息与代币供需没有清晰关系，只是泛泛“生态利好”。
- 核心负面事件未解决，却只选择性引用利好。
- 明显与用户交易周期不匹配，例如短线拿几周前旧闻当新催化。
