# macOS 系统高清截图流程

## 模式选择

默认使用系统高清截图。只有用户明确表示“不需要高清”“普通截图即可”时，才回退 Browser/Chrome 的页面截图能力。

系统截图的价值在于直接保留显示器输出的物理像素。不要把低分辨率浏览器截图放大后冒充高清。

## 开始前检查

1. 确认目标 Chrome 窗口所在显示器；双显示器时不要默认主屏。
2. 确认 macOS 已允许当前执行程序进行屏幕录制。
3. 若需要置前 Chrome、发送快捷键或控制窗口，确认辅助功能和自动化权限已开启。
4. 权限缺失时停止并提醒用户开启对应权限，等待用户确认后继续。

移动端额外检查：

1. 用户已准备一个可长期复用的 Chrome DevTools 设备页面。
2. 设备工具栏已经开启，并选择用户指定设备；未指定时使用 `390x844`。
3. 页面已在设备模式下刷新或重新打开，移动端 user agent、touch 和响应式初始化均已生效。

不要每次替用户临时打开或关闭调试工具。若页面未准备，提醒用户完成一次准备；此后优先复用同一页面。

## 定位显示器

先截取低风险的临时定位图：

```bash
/usr/sbin/screencapture -x -D <display-id> /private/tmp/component-display.png
```

使用图像查看能力检查定位图，确认：

- 捕获的是 Chrome 实际所在显示器
- 页面处于预期桌面端或移动端设备模式
- 组件完整可见，未被其他窗口覆盖
- 目标区域边界和留白已经确定

显示器编号不确定时逐个只读定位，不能凭主屏尺寸猜测。临时定位图不作为最终交付物。

## 生成高清截图

优先直接截取正确显示器的原始 PNG：

```bash
/usr/sbin/screencapture -x -D <display-id> <runDir>/screenshots/display.png
```

如果需要只交付组件区域，从这张原始 PNG 进行无缩放裁切。可用系统 `sips -c <height> <width> --cropOffset <y> <x>`；裁切前保留原始图，裁切后再次目视确认四边没有截断。不得使用 resize、插值放大或有损压缩。

若直接使用 `screencapture -R<x>,<y>,<width>,<height>`，注意参数通常使用全局逻辑坐标，而输出 PNG 可能使用显示器物理像素。双显示器的全局原点和缩放可能不同，因此必须先用定位图验证，不能复用上一台显示器的坐标。

## 校验

用只读命令记录实际像素：

```bash
file <screenshot.png>
sips -g pixelWidth -g pixelHeight <screenshot.png>
```

随后以原始尺寸查看成品，确认：

- 组件四边、圆角、阴影和浮层完整
- 文字与图标边缘清晰
- 没有捕获到 Codex、飞书或其他遮挡窗口
- 移动端 viewport 与报告一致
- 裁切前后没有缩放

报告记录显示器编号、原始显示器 PNG 尺寸、最终裁切尺寸、移动端设备/viewport、权限状态以及“无插值放大”。

## 普通截图兜底

仅当用户明确不需要高清时：

1. 按 `browser-actions.json` 使用 Browser/Chrome `screenshot`。
2. 仍执行组件可见性、交互状态和 PNG 存在性检查。
3. 报告明确写“普通浏览器截图，非系统高清截图”。
4. 不要求用户准备系统截图权限或移动端 DevTools 复用页面。
