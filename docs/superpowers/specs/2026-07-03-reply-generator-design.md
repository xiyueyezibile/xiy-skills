# reply-generator 设计文档

## 背景

当前仓库已有若干面向具体任务的 skill，但缺少一个专门用于“根据上下文和指定模板生成自然回复”的 skill。用户明确希望这个 skill 能基于 `references/` 中维护的模板库，结合聊天上下文、场景和风格要求，生成不带明显 AI 味的回复，并尽量贴近上下文里用户本人的说话方式。

这个 skill 不是单纯的固定文案模板拼接器，而是一个“模板约束 + 上下文模仿”的回复生成器：

1. 有明确模板时，优先按模板约束输出。
2. 有上下文时，优先模仿上下文中的说话习惯。
3. 模板和上下文冲突时，优先保证场景安全和语言自然。

## 目标

1. 新增一个 `reply-generator` skill，用于生成聊天、职场沟通、评论区等场景下的回复。
2. 支持两类输入：
   - 用户直接提供聊天记录、对话片段或原始语境
   - 用户只描述场景、目标和风格要求
3. 支持两类模板指定方式：
   - 直接点名模板，如“嘉豪式”
   - 只描述风格，如“阴阳一点、短一点、有梗一点”
4. 默认输出 `2-3` 个候选回复，并明确给出一个推荐项。
5. 通过 `references/` 外置模板定义，便于后续扩展人物语气、场景风格和句式骨架。
6. 保证输出尽量口语化、像人顺手打出来的内容，避免分析腔、客服腔和明显 AI 味。

## 非目标

1. 不做多轮对话代理，不负责持续扮演某个角色。
2. 不接入外部知识库、数据库或在线检索。
3. 不做自动发送、自动发布或平台适配。
4. 不在第一版实现复杂的多模板混合编排。
5. 不为每一种细分风格建立独立 skill；统一由 `reply-generator` + `references` 模板库承载。

## 核心决策

### 1. Skill 名称

使用目录名和 skill 名称：

- 目录：`skills/reply-generator/`
- frontmatter name：`reply-generator`

命名保持直白，便于用户通过“回复”“生成回复”“怎么回别人”“按某种语气回一句”等自然表达触发。

### 2. 输出策略

默认输出：

1. 如有必要，先给一句简短风险提示
2. 提供 `2-3` 个候选回复
3. 明确标注一个推荐项

不默认输出长篇解释，不展示冗长推理过程。

### 3. 输入优先级

生成时采用如下优先级：

```text
场景安全 > 上下文语气 > 指定模板 > 默认风格补全
```

解释：

- 场景安全优先：如对老板、客户、跨团队正式沟通，默认推荐项必须偏稳。
- 上下文语气优先：有原始对话时，优先学习用户侧说话方式。
- 指定模板次之：模板提供句式边界、语气强度和禁用表达。
- 默认风格补全最后：在缺少上下文时，才更多依赖模板的默认表达。

### 4. 模板命中策略

支持双通道命中：

1. **直接命中**：用户明确点名模板，如“用嘉豪的语气回”
2. **描述命中**：用户不点名模板，只描述风格，如“阴阳一点、短一点”

实现原则：

- 先尝试直接命中模板名或别名
- 未命中时，读取 `style-mapping.md` 做风格词到模板的映射
- 最多选择 `1` 个主模板，必要时只参考 `1` 个辅助模板
- 不做三个以上模板混用，避免风格发散、语气失真

### 5. 异常场景处理

当出现以下情况时，不先卡死在追问上：

- 上下文太少
- 风格要求过于抽象
- 风格与场景明显冲突，如“很阴阳地回老板”

处理规则：

1. 先用一句短提示指出信息不足或风险
2. 仍然给出 `2` 个偏保守的候选回复
3. 推荐项保持安全、自然、可直接发送

## 目录结构

建议结构如下：

```text
skills/reply-generator/
├── SKILL.md
└── references/
    ├── INDEX.md
    ├── style-mapping.md
    ├── examples.md
    └── templates/
        ├── jiahao.md
        ├── restrained-workplace.md
        ├── sarcastic-light.md
        └── friendly-banters.md
```

各文件职责：

- `SKILL.md`
  - 定义触发描述、输入提取顺序、模板命中逻辑、输出格式、异常处理
- `references/INDEX.md`
  - 汇总模板清单、别名、适用场景、关键词
- `references/style-mapping.md`
  - 维护“自然语言风格描述 -> 模板/模板候选”的映射
- `references/examples.md`
  - 提供少量高质量输入输出示例，帮助约束“不要 AI 味”
- `references/templates/*.md`
  - 每个模板一个文件，定义风格边界和示例

## SKILL.md 行为流程

`SKILL.md` 建议明确要求模型按以下顺序工作：

### 1. 提取输入要素

优先提取并理解：

1. 用户要回复谁
2. 当前场景类型：
   - 聊天
   - 职场沟通
   - 评论区/帖子互动
   - 其他口语化场景
3. 原始上下文：
   - 对方说了什么
   - 用户之前怎么说
   - 情绪和语气线索
4. 风格要求：
   - 模板名
   - 人设口吻
   - 风格描述
   - 长短要求
5. 风险信号：
   - 是否正式
   - 是否可能冒犯
   - 是否上下文不足

### 2. 选择模板

- 如果用户直接点模板，优先读取对应模板文件
- 如果用户只给风格描述，先读 `style-mapping.md`
- 如果命中多个候选，以场景最适配者为主模板
- 只在必要时引入一个辅助模板参考

### 3. 执行上下文模仿

有聊天记录时，优先模仿用户侧的：

- 句长
- 停顿方式
- 高频词
- 句尾习惯
- 情绪强度

约束：

- 模仿语感，不机械复述原句
- 不为了模仿而复制口头禅到失真
- 正式场景下，允许比原始上下文更稳一点

### 4. 生成候选回复

默认输出 `2-3` 个候选，且候选之间必须有可感知差异：

- 一个更贴近原话
- 一个更顺嘴、更像聊天
- 一个更克制或更有梗

推荐项只保留一个，不加长篇说明。

## 模板文件规范

每个模板文件统一采用固定结构，避免只堆少量例句导致模型只学到表层词汇。

推荐模板结构：

```md
# 模板名
## 定位
## 适用场景
## 不适用场景
## 语气特征
## 节奏与长度
## 常用句式骨架
## 高频表达偏好
## 禁用表达
## 生成约束
## 示例
```

字段说明：

- `定位`
  - 一句话说明模板气质
- `适用场景`
  - 说明什么语境下适合启用
- `不适用场景`
  - 说明什么语境必须避免
- `语气特征`
  - 描述情绪强度、语气冷暖、是否带刺
- `节奏与长度`
  - 说明偏短句、两段式、留白式等节奏
- `常用句式骨架`
  - 提供可迁移的句型框架
- `高频表达偏好`
  - 记录常见连接词、停顿词、句尾偏好
- `禁用表达`
  - 列出 AI 味重、客服味、鸡汤味、说教味的典型表达
- `生成约束`
  - 限制过度夸张、过度押梗、过度阴阳等问题
- `示例`
  - 提供 `3-5` 组高质量输入输出示例

## 示例模板：嘉豪式

以用户给出的例子，`jiahao.md` 可包含类似定义：

- 定位：熟人间轻吐槽，表面平静，轻微带刺，但不过分攻击
- 适用场景：熟人聊天、群聊接话、朋友间调侃
- 不适用场景：正式汇报、对上沟通、首次联系、客户沟通
- 常用句式骨架：
  - “某人怎么样怎么样，我怎么样怎么样，就很……”
  - “你这个事情吧，放别人那可能还行，放你这就……”
- 生成约束：
  - 留一点空，不解释太满
  - 不要每句都阴阳
  - 不用大段排比
  - 不上升到攻击人格

## 输出格式

默认输出结构建议固定为：

```md
风险提示：
<仅在需要时出现，一句即可>

候选 1：
<回复内容>

候选 2：
<回复内容>

候选 3：
<回复内容>

推荐：
候选 2
```

补充规则：

1. 如果用户明确说“只给一句”，则只输出一句，不强行给三条
2. 如果场景正式，推荐项默认偏稳
3. 不默认解释“为什么这样写”
4. 回复内容应可直接复制发送

## references/INDEX.md 设计

建议使用表格，统一列出模板元信息：

```md
## Reply Templates Index

| 模板 | 别名/关键词 | 适用场景 | 风格标签 | 文件 |
|---|---|---|---|---|
| 嘉豪式 | 嘉豪, 轻阴阳, 熟人吐槽 | 熟人聊天, 群聊接话 | 吐槽, 留白, 带刺 | templates/jiahao.md |
```

用途：

- 支持快速选择模板
- 支持后续新增模板时做统一维护
- 降低 `SKILL.md` 体积

## style-mapping.md 设计

这个文件负责把用户口语化要求映射到模板候选，不要求复杂算法，只要规则清晰。

建议结构：

```md
## 风格词映射

### 轻阴阳 / 带点刺 / 阴阳一点
- 优先模板：`jiahao`
- 备选模板：`sarcastic-light`
- 备注：正式场景降级使用

### 克制礼貌 / 稳一点 / 职场一点
- 优先模板：`restrained-workplace`
```

规则要求：

- 映射写“优先模板 + 备选模板 + 风险提示”
- 避免把自然语言风格词直接写死在 `SKILL.md`

## examples.md 设计

`examples.md` 只放少量高质量示例，作用是给 skill 提供风格边界，而不是变成海量语料库。

建议包含：

1. 熟人聊天示例
2. 轻吐槽示例
3. 职场克制回复示例
4. 上下文不足时的保守输出示例
5. 风格冲突时的风险提示示例

## README 更新要求

按照仓库规则，新增 skill 后必须同步更新 `README.md`，至少补充：

1. `reply-generator` 的下载命令
2. 功能简介
3. 典型使用场景
4. 简单用法示例

建议新增条目形式与现有 skill 保持一致，例如：

```bash
npx skills add xiyueyezibile/xiy-skills@reply-generator -g -y
```

README 说明重点：

- 可以根据聊天记录生成回复
- 可以按指定模板或风格生成回复
- 会尽量贴近上下文说话习惯
- 默认输出多个候选并给推荐

## 实现边界

第一版建议只做以下最小闭环：

1. 新建 `skills/reply-generator/`
2. 编写 `SKILL.md`
3. 建立 `references/INDEX.md`
4. 建立 `references/style-mapping.md`
5. 提供至少 `3-4` 个模板文件
6. 提供 `examples.md`
7. 更新 `README.md`

暂不做：

- 自动评分
- 模板测试脚本
- eval 基准集
- 多模板复杂融合逻辑

## 风险与约束

### 1. 风格过拟合

如果模板文件过度依赖个别口头禅，输出容易变成机械模仿。解决方式是强调“句式骨架和语气特征”而不是堆同一句型。

### 2. 上下文不足

当用户只给一句非常抽象的要求时，输出自然度会下降。第一版用“风险提示 + 保守候选”处理即可。

### 3. 正式场景翻车

人物风格模板在职场场景中容易越界，因此 `SKILL.md` 必须把“场景安全优先”写清楚。

### 4. 模板膨胀

后续模板变多后，若没有稳定索引，容易命中不准。第一版通过 `INDEX.md + style-mapping.md` 控制复杂度。

## 后续实现计划建议

进入实现阶段后，建议拆成以下步骤：

1. 创建 `reply-generator` skill 目录和基础文件
2. 编写 `SKILL.md` 主流程
3. 编写模板索引和风格映射
4. 补充首批模板文件
5. 更新 `README.md`
6. 用若干示例提示词做人工试跑，检查是否存在 AI 味、解释味和模板失真
