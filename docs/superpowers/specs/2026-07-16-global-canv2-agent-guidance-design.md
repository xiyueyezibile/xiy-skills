# 全局 canv2 主会话指令迁移设计

## 目标

让此用户账号下新启动的 Codex 主会话默认遵循现有 `~/.codex/agents/canv2.toml` 中的角色、语言、行为和工作方法，而不再要求用户每次显式调用 canv2 子智能体。

## 方案

在 `~/.codex/AGENTS.md` 写入 canv2 的完整 `developer_instructions`，保持原文和语义不变。若目标文件已经存在，则先保留原内容，并把 canv2 指令作为独立章节追加，避免覆盖其他全局约定。

不修改 `~/.codex/agents/canv2.toml`：它继续作为可显式派生的自定义子智能体配置。也不修改仓库级 `AGENTS.md`，因此仓库仍可通过更具体的嵌套规则补充全局规则。

## 验证

写入后检查目标文件内容完整，确认 canv2 的全部指令均存在且没有意外改写。随后启动一次非交互 Codex 会话并让它输出简短问候，验证响应使用中文且以 `CAN：` 开头；如果外部认证或运行环境阻止启动，则至少完成静态内容比对并明确说明限制。

## 风险与回退

原样迁移会保留“必须多轮追问”“不需要编写测试”等强约束，可能影响所有主会话的执行效率和验证策略，这是用户明确选择的行为。回退方式是删除 `~/.codex/AGENTS.md` 中新增的 canv2 章节；自定义子智能体文件不受影响。
